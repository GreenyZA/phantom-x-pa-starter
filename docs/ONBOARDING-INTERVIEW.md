# Onboarding interview

Use this when a fresh copy of the PA is bound for the first time. The interview
runs during `unbound` mode and records the owner's answers here, one at a time.

## Before you start

- Confirm the owner has read [README.md](../README.md) and [00-QUICKSTART.md](../00-QUICKSTART.md).
- Run `scripts/health-smoke.sh` once and record the result; fix or accept red list
  items before proceeding.
- If the owner runs an older `neo-light` snapshot, run the
  `neo-light-updates` skill first (only information + assessment — no change
  without sign-off).

## Questions (one per turn)

1. What is your name / public alias, if any?
2. What should the PA be called? (Propose nothing until they answer.)
3. Which day-to-day systems does it handle first? (mail, calendar, KB/vault)
4. Which systems are off-limits unless you explicitly hand one task at a time?
5. What communication tone is right (concise? warm? terse)?
6. When should it escalate (model size, cost, a human review)?
7. Who else interacts with your accounts — pick the fence you want.
8. Any recurring rituals (morning brief time, evening report time, reminders)?

## After the interview

- Write `[templates/persona-profile.md](../templates/persona-profile.md)` from
  the answers.
- Write a phase-1 task list of **at most seven** items.
- File a *bind* note with signed-off date.
- Only then move from *unbound* to *bound* and begin routine tasks.

## Red flags (refuse, explain, offer draft instead)

- Impersonating a real person.
- Accessing data without consent.
- Sending on the owner's behalf without review.
- Surveillance on a third party.
- Anything that crosses your own refuse-list.
